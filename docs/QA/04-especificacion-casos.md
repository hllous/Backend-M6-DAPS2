# 04 — Especificación de casos de prueba

Entregable 4 de QA. Versión del 03/11/2026. Cada caso apunta a un criterio de [02-historias-y-criterios.md](02-historias-y-criterios.md) y figura en [03-matriz-trazabilidad.md](03-matriz-trazabilidad.md).

## Cómo leerla

- **Tipo:** **Positivo** (camino válido), **Negativo** (entrada o estado inválido, o falla externa que debe rechazarse) y **Borde** (límite, caso especial, concurrencia, degradación). La meta de la cátedra es que al menos el 40 % sean negativos o de borde: el cálculo está al final.
- **Pasos y resultado esperado:** salvo que se indique otra cosa, son el CUANDO y el ENTONCES del criterio. Los **datos** y la **precondición** son los específicos del caso.
- **Prioridad:** Alta para HU Must, Media para Should y Baja para Could (la prioridad de la HU, no del caso).
- **Automatizado:** **Sí** si hay al menos un test del backend verificado, **Sí (FE)** si solo hay un test del frontend por nombre de archivo (contenido sin revisar) y **No** si no hay ninguno; en ese caso la columna Test explica cómo se prueba.
- **Estado:** "—" si el caso no se ejecutó en esta pasada. Los casos de un criterio con corrección posterior a la HU (ver [02-historias-y-criterios.md](02-historias-y-criterios.md)) dicen **Corregido** con el ID de la corrección, el issue y la fecha, y **Pasó** solo con evidencia de CI (el test existe en develop y el job de CI fue verde en el commit que lo introdujo y en el HEAD `f288d31`, run 41551982813); si no, "ejecución pendiente". Los casos de frontend no se ejecutaron.
- Los casos CP-285 en adelante se agregaron al incorporar las correcciones posteriores: cada uno pertenece a un criterio nuevo.
- Las rutas de test son de este repo, salvo las que empiezan con `Frontend-M6-DAPS2/`.
